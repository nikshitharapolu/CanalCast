# Local Canal route comparison with optional draft-loss modeling

This change builds CanalCast around a typed calculation core, local CSV loading, deterministic route selection, historical context, and an opt-in draft-loss adjustment. The pure-core boundary, zero-duration fuel handling, exact fuel-type matching, metric-specific tie tolerances, optional-history isolation, and localhost binding are present. The default path nevertheless promotes partial sailing fuel into headline voyage cost and CO₂, while selection and draft-loss error paths produce claims or values unsupported by their inputs. Provenance and several UI disclosures also fall short of the product contract.

**Watch for:** **high · confirmed** sailing-only fuel is presented and selected as complete voyage cost/CO₂; **high · confirmed** deadline/Suez states produce false “neither route” conclusions; **high · confirmed** enabled draft loss substitutes or retains unadjusted payload when its slope is missing.

**Verdict**: NEEDS_CHANGES

## High-level view

Filesystem access remains in the loader; calculation, result, comparison, and explanation modules have no file/network I/O. Missing optional history does not block the simulator, and Streamlit binds locally.

Zero-duration waiting and canal fuel resolve without a rate. **Confirmed:** the UI defaults to a positive 12-hour canal duration with no canal fuel rate, making the true total unavailable, yet displayed voyage cost and CO₂ use sailing fuel alone without showing that basis.

The core applies the specified per-metric tie tolerances and final Panama convention. **Confirmed:** unavailable deadlines and excluded options collapse into the same “no feasible candidate” state, while the UI and explanation call every resolved tie a Panama convention even when lower journey time selected Suez.

The Panama-only draft adjustment is off by default. **Confirmed:** enabling it without a loaded slope either injects a hard-coded 100 or leaves loaded TEU unadjusted; **confirmed:** the UI still labels draft “context only” while it drives payload.

**Confirmed:** result provenance omits most scenario inputs and the emission factor, and the loader rewrites statuses that should be rejected. **Likely:** Community Cloud guidance conflicts with the local-only boundary. **Confirmed:** no rendered-UI tests cover these claims despite the README saying otherwise.

## Sailing-only fuel is promoted to complete voyage economics and emissions

The **high-severity, confirmed** failure starts after the fuel breakdown correctly marks a positive-duration line item without a rate unavailable: `compute_option` falls back to `sailing_fuel` and passes it to both `voyage_fuel_cost_usd` and `co2_tank_to_wake_t` (`src/canalcast/comparison.py:259-273`, `src/canalcast/comparison.py:352-357`). Its partial-basis note is stored only in `units["fuel_for_cost_basis"]` (`src/canalcast/comparison.py:420-421`), which the UI never reads; the figures are shown as “Voyage fuel cost” and “Fuel-combustion CO₂” (`src/canalcast/ui/views.py:252-265`) and remain eligible for lowest-cost/lowest-CO₂ selection.

This is the default screen: canal fuel rate is unresolved (`src/canalcast/models.py:241-242`) while canal duration starts at 12 hours (`src/canalcast/ui/controls.py:682-687`). A direct run returned an unavailable total with numeric voyage cost and CO₂. Requirements 3, 7.5, 8.1/8.5, and 9.1 require those dependent outputs to remain unavailable. Pass the true total into cost and CO₂; if partial estimates become a separate product feature, give them separate fields and labels and exclude them from the existing priorities.

## Unknown deadlines and excluded Suez routes become false deadline failures

This **high-severity, confirmed** branch first sets `feasible=None` and `deadline_status="undetermined"` for a missing deadline (`src/canalcast/comparison.py:360-365`), then treats the absence of any `feasible is True` candidate as a miss and emits “Neither route meets the deadline” (`src/canalcast/comparison.py:722-740`). A direct `deadline_h=None` run returned two undetermined statuses plus that factual-negative selection message instead of disabling selection and naming the missing deadline.

Exclusion triggers the same contradiction. For Singapore–New York at 18 kn, Panama took about 704.0 hours and Suez 564.7; with a 634.4-hour deadline and `suez_available=False`, Suez was feasible and excluded, Panama missed, yet selection and the UI said neither route met the deadline. Model “deadline unavailable,” “no available option meets,” and “neither computed route meets” separately, with closest-option copy explicitly scoped to non-excluded options.

## Lower-journey tie resolution is mislabeled as the Panama convention

This **medium-severity, confirmed** presentation bug discards the core’s distinction between “resolved by lower journey time” (`src/canalcast/comparison.py:807-810`) and the final Panama convention (`src/canalcast/comparison.py:818-821`). Both explanation and view check only for a non-null resolution and claim the Panama convention settled it (`src/canalcast/explain.py:198-203`, `src/canalcast/ui/views.py:332-337`). In a reproduced cost tie, Suez won on lower journey time while the explanation claimed a Panama tie-break; condition the convention copy on the actual final tie step.

## Enabled draft loss fails open when the loss slope is unavailable

This **high-severity, confirmed** missing-input violation has two paths. `containers_lost_seed` substitutes a hard-coded 100 when the loaded Requirement 20.5 slope is absent or unparsable (`src/canalcast/ui/controls.py:272-292`), and the enabled slider turns it into an explicit override. A direct core caller without that context value starts from `loaded = base_loaded` and deliberately keeps it when loss calculation fails (`src/canalcast/comparison.py:282-286`, `src/canalcast/comparison.py:335-339`); the reproduced enabled result retained 8,500 TEU and a numeric per-TEU cost with no loss figures. Reject enabling until inputs exist or return affected loaded-TEU/per-TEU outputs as `Unavailable` rather than silently using feature-off payload.

## Active draft modeling is still labeled “context only”

This **medium-severity, confirmed** contradiction appears in the custom control, which always says draft is “context only” and “does not reduce TEU, cost, or CO₂” (`src/canalcast/ui/controls.py:495-500`), and the unconditional “Canal draft (context only)” disclosure heading (`src/canalcast/ui/views.py:527`). With Requirement 20 on, draft reduces Panama loaded TEU and raises fuel cost per TEU. Switch this copy with the toggle and distinguish unchanged voyage fuel cost/CO₂ from changed per-TEU cost.

## Displayed provenance omits result-driving inputs

This **medium-severity, confirmed** traceability gap is visible in `input_provenance`: it contains ship/curve and route records plus optional rates, but omits speed, load factor, bunker price, canal/wait durations, deadline, Suez availability, selected fuel type, and emission factor (`src/canalcast/comparison.py:383-418`). The renderer also omits retained values, units, methods, and derivations (`src/canalcast/ui/views.py:429-436`). Carry all scenario and factor provenance into the result and render the value/unit/source/status/date and derivation required by Requirements 2, 11.10, and 15.1.

## Status validation rewrites forbidden vocabulary

This **medium-severity, confirmed** contract breach maps `secondary_source` and `analyst_estimate` to `approximate` (`src/canalcast/loader.py:117-121`, `src/canalcast/loader.py:199-216`), coerces arbitrary context statuses to `approximate` (`src/canalcast/loader.py:485-489`, `src/canalcast/loader.py:548-552`), and defaults unknown optional-series status to `sourced` (`src/canalcast/loader.py:842-845`). Requirements 2.2-2.3 require rejection with the original value reported. Normalize existing CSV rows—including the now-computational draft slope—to the four-value vocabulary, then reject or mark future invalid records unavailable rather than upgrading their trust classification.

## Local-only runtime conflicts with cloud deployment guidance

This **medium-severity, likely** deployment conflict pairs a correct `localhost` bind (`.streamlit/config.toml:1-6`) with instructions to use Streamlit Community Cloud while claiming v1 has no public endpoint (`README.md:94-97`). A working cloud deployment needs a remotely reachable listener/endpoint, so the platform must either override the restriction or the documented deployment is unreachable. Keep v1 guidance local/private-only, or document and enforce the private mechanism that satisfies Requirement 19.3.

## Rendered behavior lacks regression coverage

This **low-severity, confirmed** gap leaves the metric labels, missing-input state, Suez exclusion, tie caption, draft-mode labels, provenance panel, and missing-history chart unrendered by tests, although the README says the UI is smoke- and example-tested (`README.md:147-149`). Add focused Streamlit/AppTest coverage and correct the claim until it exists. During this review, 25 loader/no-I/O/draft-disclosure tests passed; full collection could not run because Hypothesis is absent from the environment, so property tests were inspected but not executed.
